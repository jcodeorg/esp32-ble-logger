# ESP32 BLE Environment Logger

ネットワーク設定（Wi-Fi等）を行わず、**ESP32（MicroPython）のRAM上に環境ログを蓄積**し、**Chromebook（Web Bluetooth API）から無線で回収・蓄積**するためのオフライン環境ロガーシステムです。

フラッシュメモリへの書き込みを「ゼロ」にすることで、**メモリの寿命を気にせず長期間運用**できます。また、数日ごとの回収データをブラウザ側で1つのファイルにまとめられるため、2週間程度の長期計測データもスッキリ管理できます。

---

## 🛠 システムの特長

1. **フラッシュメモリの寿命が「無限」**
* センサーデータはすべてRAM（メモリ）上のリストに保持するため、フラッシュストレージへの書き込み・消去による劣化が一切ありません。


2. **Wi-Fi設定不要でセキュア**
* 複雑なルーターのパスワード設定などは不要。Bluetooth Low Energy (BLE) を使って、Chromebookと直接1対1で通信します。


3. **ファイルが散らからない（ブラウザ側でのデータ蓄積）**
* 数日おきにデータ回収を行っても、Chromebook側のブラウザがデータを自動で蓄積。2週間分のデータ（約336件）を「1つの綺麗なCSVファイル」として最後にまとめて保存できます。


4. **安全なデータ管理**
* Chromebook側で1つのファイルに結合・保存が完了したことを確認してから、デバイス側に「データ消去コマンド」を送るため、データの取りこぼしを防げます。


5. **自動時刻同期**
* ChromebookとBluetoothで接続した瞬間に、現在の正確なPC時刻がデバイスに送信され、内蔵RTC（リアルタイムクロック）の時刻が自動修正されます。

## 🧩 複数デバイス構成への対応

このプロジェクトは、センサー・アクチュエータ構成が異なる複数のデバイスを、共通の基盤（BLE通信・データ蓄積・時刻同期・WDTなど）を再利用しながら管理できるように設計されています。

* `firmware/main.py` はBLE通信・ログ蓄積・OLED表示・WDTなど全デバイス共通のロジックのみを持ちます。
* センサーの読み取りやアクチュエータの制御など、デバイス固有の処理は `firmware/sensors.py`（標準構成）または `firmware/sensors_actuators.py`（ポンプ・LED構成）に分離されています。
* `main.py` 冒頭の `ACTIVE_PROFILE` 変数（`"soil_cds"` または `"pump_led"`）を書き込み対象のハードウェアに合わせて切り替えるだけで、同じ `main.py` を両方の構成で使い回せます。
* 各ファイルは次の共通インターフェースを実装します。

  | 関数/変数 | 役割 |
  |---|---|
  | `DEVICE_TYPE` | BLEデバイス名（例: `DeviceType-xxxxx`）に埋め込む構成の識別子 |
  | `CSV_FIELDS` | `read_sensor()` が返す値のキーを、CSV出力・OLED表示に使う順序で並べたリスト |
  | `init_sensors(i2c)` | センサーの初期化（起動時に1回） |
  | `read_sensor(i2c)` | センサー値を `dict` で返す（計測・OLED更新のたびに呼ばれる） |
  | `init_actuators()` | アクチュエータの初期化（起動時に1回。アクチュエータが無ければ何もしない） |
  | `tick_actuators(now_epoch)` | アクチュエータのタイマー制御（メインループから毎秒呼ばれる） |

* 新しいデバイス構成を追加したい場合は、`firmware/` に上記インターフェースを満たす新しいファイル（例: `sensors_xxx.py`）を追加し、`main.py` の `ACTIVE_PROFILE` 判定に分岐を足すだけで対応できます。

* **ESP32開発ボード**（Bluetooth内蔵）
* **温湿度センサー**（AHT20）
* **土壌水分センサー**（ADC接続）
* **CdS照度センサー**（ADC接続）

```text
├── boot.py             # 起動時の初期設定（NeoPixcel消灯）
├── main.py             # メイン処理（計測・BLE・データ管理。デバイス構成は共通）
├── sensors.py          # 標準構成: 土壌水分センサー + CdS照度センサー
└── lib/                # センサー等の共通ドライバ
    ├── ahtx0.py        # 温湿度センサー(AHT20)
    └── ssd1306.py      # OLEDディスプレイ
```


### 別構成（`pump_led`）
* **ESP32開発ボード**（Bluetooth内蔵）
* **温湿度センサー**（AHT20）
* **照度センサー**（BH1750, I2C接続）
* **水中ポンプ**（リレー/MOSFET経由でGPIO制御）
* **LED照明**（リレー/MOSFET経由でGPIO制御。タイマーで点灯・消灯）

```text
/
├── boot.py             # 起動時の初期設定（NeoPixcel消灯）
├── main.py             # メイン処理（計測・BLE・データ管理。デバイス構成は共通）
├── sensors_actuators.py # 別構成: 照度センサー(BH1750) + 水中ポンプ + LEDタイマー制御
└── lib/                # センサー等の共通ドライバ
    ├── ahtx0.py        # 温湿度センサー(AHT20)
    ├── ssd1306.py      # OLEDディスプレイ
    └── bh1750.py       # 照度センサー(BH1750)
```

## 🚀 使い方・運用フロー（2週間・1時間おき計測の場合）

### 1. デバイス側（ESP32）の準備

1. ESP32に MicroPython のファームウェアを書き込みます。
2. `firmware/` 内の `boot.py`、`main.py`、`sensors.py`、`sensors_actuators.py`、`lib/` フォルダをすべて ESP32にアップロードします（Thonny IDE などの使用が便利です）。
3. `main.py` 冒頭の `ACTIVE_PROFILE` を、実際に搭載したセンサー・アクチュエータ構成（`"soil_cds"` または `"pump_led"`）に合わせて設定してから書き込みます。
4. 電源を入れると、1時間ごとにセンサー値を取得し、RAM上にタイムスタンプ付きで記録し始めます。

### 2. 受信側（Chromebook）の準備

https://jcodeorg.github.io/esp32-ble-logger/  を開きます。

又は、
1. `webapp/` フォルダ内の `index.html` を任意の場所に保存します。
2. Chromebookの **Google Chrome** で `index.html` をダブルクリック（またはブラウザにドラッグ＆ドロップ）して開きます。

### 3. データの回収と蓄積フロー

* **随時（1日1回など）の回収:**
1. ChromebookとデバイスをBluetoothで接続（接続時に自動で時刻同期されます）。
2. **[データを取得して蓄積]** ボタンを押すと、その時点までのRAM上のログがブラウザに読み込まれ、これまでのデータに自動で追加（マージ）されます。


* **計測完了時:**
1. デバイス別データ管理画面で、デバイス名の右側にある **[CSV保存]** ボタンを押すと、これまで蓄積したデータがCSVファイル（例: `environment_log_2weeks.csv`）としてダウンロードされます。
2. ダウンロードが完了したら、［削除］ ボタンを押して蓄積データをクリアし、次回の計測に備えます。

## 💡 運用上の注意点

* **電源断について:** デバイスの電源が切れる（停電など）と、RAM上のデータは揮発するため消えてしまいます。「電源が入っている期間のデータを、数日おきに回収して蓄積する」という用途に最適です。
* **Bluetoothの接続仕様:** Web Bluetoothのセキュリティ上の制約により、接続やデータ取得の際は必ずブラウザ上のボタンをクリックする必要があります。
* **Thonnyでのメンテナンス時の注意（WDT）:** `main.py` は長時間稼働のためウォッチドッグタイマー(WDT)を使用しています。ESP32のWDTは一度起動すると停止できないため、Thonnyで接続してコードを止めたまま編集していると、feed()が呼ばれずに強制リセットされることがあります。5分以上メンテナンス作業を行う際は、あらかじめデバイス上に `maintenance.flag` という空ファイルを作成してから再起動してください（Thonnyのファイルビューで新規作成できます）。このファイルが存在する間はWDTが起動しないため、安心して編集・デバッグができます。作業が終わったら `maintenance.flag` を削除し、再起動してWDTを再度有効化してください。
